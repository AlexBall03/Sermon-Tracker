## 1. What was implemented

Nothing of Phase 2F.2 or 2F.3 was built. No navigation item, setting, job, notification, or history table was added.

## 2. Why a new column

`ideas.updated_at` has `$onUpdate`, so every write to the row moves it: a status, format, type, or kind change as much as an edit to the notes. It cannot tell work from housekeeping, so it could not be reused. (Tag actions and archiving already leave it alone, on purpose.)

`ideas.last_developed_at`: `timestamp with time zone`, nullable, no default, no backfill. The migration is one statement:

```sql
ALTER TABLE "ideas" ADD COLUMN "last_developed_at" timestamp with time zone;
```

It alters no existing value and is safe under the code now live, which never names the column, and after a rollback. The file was generated by `npm run db:generate` and renamed from its generated name to `0010_idea_last_developed` (the `.sql` file and its `tag` in `drizzle/meta/_journal.json`) before it was applied anywhere; its SQL was not edited.

## 3. What counts as development

When an idea was last worked on is `coalesce(last_developed_at, created_at)`.

| Write                                                                                   | Sets `last_developed_at` |
| --------------------------------------------------------------------------------------- | ------------------------ |
| `updateIdea`, when the title, subject, notes, or passages differ from what is stored    | Yes                      |
| `attachReferences` (from the Bible reader or saved Scripture), when a passage was added | Yes                      |
| `createIdea`                                                                            | No, it stays null        |
| `updateIdea` sending the same content with another status, format, type, or tags        | No                       |
| `classifyIdea`, `setIdeaKind`, the tag actions, `archiveIdea`, `restoreIdea`            | No                       |
| `attachReferences` naming only passages the idea already has                            | No                       |
| Anything in `src/features/preaching`                                                    | No                       |

"Passages differ" means which passages, their order, or which is the main text. The editor sends the whole draft on every save, so `updateIdea` now reads the owner's row `FOR UPDATE` and its references inside its transaction, compares, and adds the date to the same owner-scoped update only when something differs. The date is the server's clock; nothing from the browser reaches it.

**Existing records.** Every idea from before `0010` has a null date and is measured from its creation. The migration made none look active, and a status change, a tag, or an archive after deployment cannot reset one: only real work does.

## 4. Dashboard: selection rules

`revisitIdeas(db, ownerId, limit = 3, now)` in `src/features/ideas/ideas.ts`. An idea is eligible when all of these hold:

- it is the signed-in account's own (owner in the WHERE clause);
- it is filed as a sermon (points and undecided ideas never appear);
- it is not archived;
- its status is Idea, Developing, or On Hold (`unfinishedStatuses`). Ready is the one finished status. There is no preached status, and the Preaching Record is not consulted: a preached sermon is finished only if its status says so;
- it was last worked on 30 days ago or more (`revisitAfterDays` in `src/features/ideas/model.ts`, the one place the number lives).

Order, the same every time:

1. never developed since capture, status Idea or Developing;
2. developed before, status Idea or Developing;
3. On Hold, which was put aside on purpose;

then the longest wait first, then the ID. The database filters, orders, and limits to three; the page reads three rows at most.

`RevisitIdeas` (`src/features/dashboard/components/revisit-ideas.tsx`) is a panel beside "Recent ideas", where the shortcut cards were (settings and administration are in the account menu only; "Record preaching" is a button in the page's header). Each row is one link to the idea's page, with its title, its status, and "Never developed · created Oct 1, 2026" or "Last developed Aug 3, 2026". At its foot is "See all that need attention", which opens Sermon Ideas with that filter on.

| Account                                         | What is shown                                                    |
| ----------------------------------------------- | ---------------------------------------------------------------- |
| No ideas, or every idea archived                | The section is not drawn; "No ideas yet" stands alone, as before |
| Ideas, but no unfinished sermon is 30 days idle | The heading, one line saying so, and a link to Sermon Ideas      |
| One or two eligible                             | One or two cards; nothing fills the rest                         |

## 5. Library: filters and sorting

- `LibraryQuery.revisit` is `"never"`, `"attention"`, or null; the URL parameter is `revisit`. It is parsed, serialized, counted, and cleared by `src/features/ideas/library-query.ts` like every other filter, so back and forward, the return to page 1, "Clear filters", the chip, and the "no ideas match these filters" empty state all work as they did.
- **Never revisited**: sermons with a null `last_developed_at`, whatever their status or age. A sermon captured yesterday is here; so is a Ready one. Combine it with Status to narrow.
- **Needs attention**: the dashboard's rule exactly (`needsAttention`), without the archive condition, which stays with the existing Show control (active by default).
- Both find sermons only, as the sermon type and format filters do, and hold together with search, kind, status, type, format, tags, dates, and the archive view.
- The group is called "Revisit" in the existing filter panel, one of the two or neither, with a line beneath that says what the chosen one finds. Nothing was added to the library overview, Saved Scripture, or the Preaching Record.
- While either is on, a result shows the `DevelopedLine` in place of "Updated …", in both card and list views.
- Sorting: Recently updated, Least recently updated, and Recently created already existed (`updated-desc`, `updated-asc`, `created-desc`). They still sort by `updated_at` and `created_at` and say "updated"; no order sorts by development.

## 9. Known limitations

- **Work done before `0010` is not known.** A sermon developed at length last month reads as "Never developed" until its content is next edited, and may be suggested once it is 30 days old. `updated_at` could not be used to fill the column in, because a status change moves it. This fades as ideas are worked on.
- **A title change counts as development**, however small. So does reordering passages.
- **On Hold ideas are suggested**, last. If parked ideas should stay out of sight, take `on_hold` out of `unfinishedStatuses`; the dashboard and the filter both follow.
- **"Never revisited" has no age or status rule**, as briefed, so it includes sermons captured today and Ready ones.
- **Dates are UTC days**, as everywhere else in the library, and the 30 days are counted to the instant, not to the calendar day.
- **An idea's own page does not show the date.** It appears on the dashboard and in filtered results only.
- **The Spanish strings were not seen on screen.**
- Carried from Phase 2E.2 and unchanged: the end-to-end suite and the signed-in browser pass are outstanding.
