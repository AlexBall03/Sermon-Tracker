## B. Database

| Table                   | Purpose                               | Key constraints                                                                                              |
| ----------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `preaching_venues`      | Where; reusable                       | `UNIQUE (owner_id, lower(name))`; `UNIQUE (id, owner_id)`; name 1–80, locality null or 1–120                 |
| `preaching_contexts`    | What kind of occasion; reusable       | The same, without `locality`                                                                                 |
| `preaching_occurrences` | One occasion a sermon was preached on | Composite FKs to `ideas`, venues, and contexts, each with `owner_id`, each `ON DELETE RESTRICT`; five CHECKs |

Occurrence columns are exactly the brief's: `id`, `owner_id`, `sermon_id`, `preached_on` (`date`), `time_of_day` (`am`/`pm`/null), `venue_id`, `context_id`, `actual_format` (default `unspecified`), `duration_minutes` (0–1440 or null), `notes` (≤5,000), `recording_url` (`https://…`, ≤2,048), `created_at`, `updated_at`.

Indexes: `(owner_id, preached_on desc, id desc)`, `(sermon_id, preached_on desc)`, `(venue_id)`, `(context_id)`, and the two name indexes.

**The migration only adds.** It was generated by `npm run db:generate` and not edited. It alters, drops, and rewrites nothing, creates no rows, and is safe under the code currently live.

**Applied to development:** yes, with `npm run db:migrate:dev`; `npm run db:status` then showed 10 applied, 0 pending. **Not applied to production**; nothing was done to production.

## C. Services and their contracts

All take `(db, ownerId, …)`; the owner comes from the caller's session and is in every WHERE clause.

**`occurrences.ts`**

| Function                                                 | Returns                                                                                                                          |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `createOccurrence(db, ownerId, input, id?)`              | `{ status: "created" \| "existing", occurrence }`, or `missing`, `not_sermon`, `unknown_venue`, `unknown_context`, `unavailable` |
| `getOccurrence(db, ownerId, id)`                         | `HistoryItem \| null` (the occasion with its sermon, venue, and context)                                                         |
| `updateOccurrence(db, ownerId, id, change)`              | `{ status: "updated", occurrence }`, or `missing`, `unknown_venue`, `unknown_context`                                            |
| `deleteOccurrence(db, ownerId, id)`                      | `boolean`                                                                                                                        |
| `searchHistory(db, ownerId, query?, pageSize?)`          | `HistoryPage`: `items`, `total`, `page`, `pageSize`, `totalPages`                                                                |
| `listForSermon(db, ownerId, sermonId, page?, pageSize?)` | `HistoryPage` for one sermon                                                                                                     |
| `occurrenceCounts(db, ownerId, sermonIds)`               | `Map<sermonId, { count, lastPreachedOn }>`; no entry for a sermon never preached                                                 |

**`venues.ts`**: `listVenues` (alphabetical, with `occurrenceCount`), `createVenue`, `updateVenue` (name, locality, or both), `deleteVenue`. **`contexts.ts`**: `listContexts`, `createContext`, `renameContext`, `deleteContext`.

- Create and rename return `{ ok: true, venue | context }`, or `{ ok: false, reason: "duplicate", existingId }`, or `{ ok: false, reason: "missing" }`. `existingId` is the record that already has the name, so picking a suggestion twice can simply use the first.
- Delete returns `{ ok: true }`, `{ ok: false, reason: "missing" }`, or `{ ok: false, reason: "in_use", count }`.

**`ideas.ts`**: `deleteIdea` now returns `"deleted" | "missing" | "preached"` (it returned a boolean).

**`actions.ts`** (server actions, each calling `authorize("active")`): `recordOccurrence(input, id?)`, `updateOccurrence(id, input)`, `deleteOccurrence(id)`, `createVenue(input)`, `updateVenue(id, input)`, `deleteVenue(id)`, `createContext(name)`, `renameContext(id, name)`, `deleteContext(id)`. They return `{ ok, message }` plus `id`, `venue`, `context`, or `existingId` where useful. The ideas `deleteIdea` action now also returns `reason: "preached"`.

**History query** (`HistoryQuery`, parsed by `historyQuerySchema`): `q`, `sermonId`, `from`, `through`, `venueIds`, `contextIds`, `formats`, `timesOfDay` (`am`, `pm`, `unspecified`), `sort` (`date-desc` default, `date-asc`), `page`.

- Search: every word, each found in the sermon's title, the venue's name or locality, or the context's name.
- Order: date preached, then PM before AM before unsaid, then `created_at`, then ID. Deterministic across pages.
- A page past the end returns the last page. Page size defaults to 24, at most 100.

## D. Validation

`preachingSchemas(locale, today?)` in `schemas.ts`, with messages in the account's language. No server code, so a form can use it.

| Field             | Rule                                                                                                         |
| ----------------- | ------------------------------------------------------------------------------------------------------------ |
| `sermonId`        | A UUID. Required on create; not accepted on update                                                           |
| `preachedOn`      | A real calendar date `YYYY-MM-DD`, from 1900-01-01, not in the future                                        |
| `timeOfDay`       | `am`, `pm`, or null                                                                                          |
| `actualFormat`    | One of the four formats; `unspecified` when a new occasion does not say                                      |
| `durationMinutes` | A whole number 0 to 1,440, or null. Zero is accepted and is not "missing"                                    |
| `notes`           | Trimmed, at most 5,000 characters; empty is null                                                             |
| `recordingUrl`    | Any `https` address with no username or password, at most 2,048 characters; empty is null. No site allowlist |
| Venue name        | Trimmed, inner whitespace collapsed, 1 to 80. Locality: the same, up to 120, optional                        |
| Context name      | Trimmed, inner whitespace collapsed, 1 to 80. Any words the account likes                                    |

- **Update semantics.** `occurrenceUpdate` and `venueUpdate`: a field left out is left alone; a nullable field given as `null` is cleared; at least one field must be named.
- **Future dates.** There is no time zone setting. "Today" is the latest date it currently is anywhere on Earth (UTC+14), so nobody is refused their own today. The cost: someone west of UTC can record a date up to a day ahead.

## E. Ownership and integrity

| Rule                                                      | Where it is enforced                                                                              |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| An occasion's sermon, venue, and context are its owner's  | The owner in every query; composite foreign keys carrying `owner_id`                              |
| Missing and someone else's are the same answer            | Owner-scoped reads; one message per kind of thing in the actions                                  |
| Only a sermon can be recorded                             | `createOccurrence`, with the idea's row locked `FOR UPDATE`                                       |
| A retry records once and overwrites nothing               | `ON CONFLICT (id) DO NOTHING`, then an owner-scoped read; the first row is returned as it stands  |
| Another account's occasion ID reveals and changes nothing | The read is owner-scoped, so the outcome is `unavailable`                                         |
| Recording changes nothing on the sermon                   | Nothing in `src/features/preaching` writes to `ideas`                                             |
| History is never erased or detached by another deletion   | `ON DELETE RESTRICT` on all three keys; `deleteIdea`, `deleteVenue`, `deleteContext` answer first |

**Concurrency with reclassification.** `setIdeaKind` is a single `UPDATE`, which takes the idea's row lock. `createOccurrence` takes the same lock before it reads `kind`. So the two always run one after the other: refiled first, the recording is refused; recorded first, the occasion stands and the refiling follows. No change to `setIdeaKind` was needed, and no new locking scheme was added. `deleteIdea` takes the lock too, so a deletion and a recording cannot pass each other.

## F. Archiving, reclassification, deletion

- **Archived sermon.** Its occasions are untouched and still returned by every history query (each item carries the sermon's `archivedAt`). Restoring changes nothing. An archived sermon can still be recorded as preached; nothing in this phase forbids it.
- **Refiled as a point or undecided.** Its occasions are untouched, readable, editable, and removable. New ones are refused (`not_sermon`). Refiled as a sermon again, new ones are accepted.
- **Deleting a sermon with history.** Refused: `"preached"`, with the message "This sermon has been preached, so it cannot be deleted. Archive it instead." The idea and its history are untouched. This holds whatever the idea is filed as now. Once its occasions are removed one by one, it can be deleted.
- **Deleting an idea without history.** As before.
- **Venue or context in use.** Not deleted: `in_use` with the number of occasions. Renaming keeps every association.
- **Deleting one occasion.** Removes that row only.

**The concurrency run.** PGlite is one connection and cannot race. A temporary test file was run once against the development database with real concurrent connections, under a throwaway account that it created and removed (it asserted the account was gone), and the file was then deleted. It showed:

- A recording started while a reclassification was uncommitted **waited**, and was then refused; when that reclassification was rolled back instead, it went through.
- A reclassification and a deletion started while a recording was uncommitted both **waited**; afterward the occasion stood, the idea was refiled, and the deletion answered `"preached"`.
- The same occurrence ID sent five times at once left one row: one `created`, four `existing`.
- Six rounds of deletion against recording ended every time as either deleted-and-missing or preached-and-created, never with history lacking its sermon.
- Six rounds of reclassification against recording ended every time as `created` or `not_sermon`, with no error.

The committed suite keeps a smaller guard: it checks, in the SQL the code sends, that `createOccurrence` and `deleteIdea` lock the idea's row before they check or insert.

## I. Known limitations and open points

- **`routes.history` in `src/lib/site.ts` still says `/history`.** It was written before History was decided to be a section of the library. It is used only by the two route lists in that file (what is never indexed, and what the proxy sends guests away from); it was left for 2E.2 to correct with the page.

- **No limit on how many venues or contexts an account has**, and their lists are not paged.
- **The idea editor does not yet treat the "preached" answer specially.** It shows the message like any other failure, which is correct but plain; 2E.2 can use `reason: "preached"` to offer Archive.
- **Tag counts, `attachReferences`, and the library** are unchanged. The library does not show whether or how often a sermon was preached; `occurrenceCounts` is there for when it should.
- **The Spanish wording is the agent's**, as elsewhere.
- **The stale saved-Scripture end-to-end test** from Phase 2C.1B is untouched.
