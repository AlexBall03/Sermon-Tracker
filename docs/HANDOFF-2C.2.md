# Phase 2C.2 Handoff — RVG, Languages, and Bilingual Reading

Written 12 October 2026. [ARCHITECTURE.md](../ARCHITECTURE.md) is the technical reference (see "Languages and translations"); [DATABASE.md](DATABASE.md) has the tables; [data/bible/README.md](../data/bible/README.md) has the RVG's source and how it was checked; this is the summary.

## A. What was implemented

- **The RVG.** The Reina-Valera Gómez, 2023 revision, from the publisher's own file, all 66 books, loaded beside the King James. It is shown as **RVG** everywhere; the year appears only in the data documentation.
- **Language preferences.** An interface language (English or Spanish) and a Bible translation (KJV or RVG) per account, independent of each other. Until a translation is chosen it follows the interface language; once chosen, changing the language does not move it. Both are in Settings, under Language.
- **Localization.** A dictionary per feature in English and Spanish, with English the fallback. Translated: the bar, tab bar, and account menu; the dashboard; the library (ideas and Saved Scripture, their controls, results, empty states, tag management); the idea page, editor, quick capture, and "Add to an idea"; the Bible reader, Scripture Panel, previews, and reference field; Settings' page, its Language, Appearance, Bible, and Account sections; Administration; the access-denied and invitation notices; and the messages of every idea, tag, saved-Scripture, preference, and admin action.
- **Translation selector** in the reader, which keeps the book, chapter, and verse, shows that it is loading, and saves the choice.
- **Side-by-side reading**, in all four pairings, each pane with its own selector, place, selection, marks, and scrolling.
- **Marks per translation**, with a line in the reader that says what was marked in the other translation and opens it.
- **The Spanish switch** for administrators, on `/admin`, enforced on the server.

**Status.** Lint and type checking are clean and the production build passes (section E). The unit, component, and database suite last ran in full at **1,059 of 1,059 passing**. After that run the only changes were one ordering fix that the build exposed (`getPreferences` reads the access check before the settings), an automatic format pass, and documentation; at the owner's instruction no further test run was made, so that last state is not re-verified by tests. The end-to-end suite was started and stopped before it finished and has **not** run for this phase. There was no measured visual pass of the kind earlier phases had; the owner exercised the reader, Settings, and comparison in a signed-in development session while the work was under way and several things were changed from that (section C).

## B. Schema and migration

One migration, `0006_scripture_translations_and_languages`, generated by `npm run db:generate`, additive only:

- **New** `scripture_verses (translation, book, chapter, verse, text)` and `scripture_psalm_titles (translation, psalm, text)`, holding both translations, with a search index that folds accented vowels.
- **New** `app_settings`, one row, `spanish_enabled` default true.
- `users` gains `locale` (default `en`) and `bible_translation` (nullable).
- The translation CHECK on `bible_favorites` and `bible_highlights` now admits `rvg`. No existing row changes.
- **`bible_verses` and `bible_psalm_titles` are left in place and are no longer read or loaded.** The deployment live while this migration runs reads `bible_verses` with no translation filter, so Spanish rows could not go there. They should be dropped by a later migration.

The loader (`scripts/db/seed-bible.mjs`, `cli.mjs`) now loads each translation into the new tables, one transaction each, skipping any already loaded. It has been applied to the **development** database (`db:migrate:dev`): 7 migrations applied, KJV and RVG and both sets of titles loaded. No production command was run.

## C. Decisions made with the owner during the work

- Marks stay per translation (the existing rule), with the note in the reader.
- The switch is off for everyone, administrators included.
- Sign-in pages follow a language cookie; the landing page stays English.
- Comparing is offered only where the window fits two columns (not on a phone held upright), and the docked navigation steps aside for the panes on mid-sized windows instead of competing with them. An earlier version that showed one pane at a time with a switch was removed.
- Changing translation shows loading at once and then an obvious change. The first version tied the change to the router's address update, which the preference save held back, so nothing appeared to happen; the pane now switches on its own state.
- The reader's navigation names the books as the text being read does (Génesis beside the RVG), whatever the interface language.

## G. Limitations and follow-ups

- **Still in English:** the public landing page; Clerk's own sign-in and sign-up forms (localizing them needs `@clerk/localizations` and a provider that can read the language without making the root layout dynamic); the profile and security forms inside Settings (name, picture, email addresses, password, connected accounts, devices) and their Clerk error messages; the three access messages from `authorize` ("Your session has ended…"); loading placeholders' screen-reader text on the sign-in pages.
- **End-to-end and visual checks were not done.** The signed-in specs still need the test account, and the new comparison layout has not been measured at phone, tablet, and desktop sizes in both themes.
- **Spanish wording** was written to be natural, not literal, but has not been reviewed by a native reader of the church's own usage. Terms worth a look: "Inicio" for Dashboard, "Biblioteca", "Capturar", "resaltado", "etiqueta".
- **RVG psalm headings** follow the publisher's file: "Aleluya" and "Alabad a Jehová" are headings in Psalms 111–113, 135, and 148–150, and Psalm 145's heading is inside verse 1. See the data README.
- **No 2010 comparison by machine**; see the data README.
- A favorite cannot be moved or copied from one translation to the other.
- Marks made in one translation are not shown in the other beyond the count.
- Comparison scrolling and navigation are independent; synchronizing them is the `linked` flag in `BibleReader`.
- On a narrow screen a comparison in the address shows the first pane only; the second returns when the screen is wide enough.
- Search results already listed stay in the translation they were searched in if the pane's translation is then changed.
- The saved copy-shortcut and reading position remain device preferences.
