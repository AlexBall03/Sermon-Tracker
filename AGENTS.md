## Sermon Tracker project notes

- Read `ARCHITECTURE.md` first; it is the technical source of truth. Current status and next steps: `docs/ROADMAP.md`, `docs/HANDOFF-1B.md`, `docs/HANDOFF-1B.1.md`, `docs/HANDOFF-1B.2.md`, `docs/HANDOFF-1C.1.md`, `docs/HANDOFF-2A.md`, `docs/HANDOFF-2B.1.md`, `docs/HANDOFF-2B.2.md`, `docs/HANDOFF-2C.1A.md`, `docs/HANDOFF-2C.1B.md`, `docs/HANDOFF-2C.1C.md`, `docs/HANDOFF-2C.2.md`, `docs/HANDOFF-2D.1.md`, `docs/HANDOFF-2D.2.md`, `docs/HANDOFF-2D.3.md`.
- Stay inside the current phase. Do not build later-phase features early.
- The repository owner manages Git. Run read-only Git commands only: no commit, stage, branch, push, pull, or config changes.
- Stop every dev, preview, or test server you start before finishing. Never kill processes you did not start.
- The repository is public. No secrets anywhere.
- Use semantic design tokens from `src/app/globals.css`; no hardcoded brand colors in components. The interface is neutral: emerald is for actions, selection, and focus, not for surfaces.
- Schema changes: edit `src/db/schema.ts`, run `npm run db:generate`, commit the SQL. Never `drizzle-kit push`, never hand-edit an applied migration, never run `db:migrate:prod` or `db:stamp`. Production is migrated by its own deployment during `npm run build` (see `docs/DATABASE.md`), so every migration must work with the code already live.
- Every page under `(app)` and every server action checks access itself with the helpers in `src/features/auth/access.ts`. The proxy is routing only.
- `npm run dev` needs a development database. Use `npm run dev:next` when none is configured.
- Idea queries live in `src/features/ideas/ideas.ts` and tag queries in `src/features/ideas/tags.ts`; every one filters by owner in its WHERE clause. Keep it that way.
- The library's search, filters, order, and page are URL parameters. Read and write them only through `src/features/ideas/library-query.ts`; never build a sort or a filter from a raw parameter. Library controls change the address only through `useLibrary().apply` (`src/features/ideas/components/library/library-state.tsx`), which builds each change on the query last asked for and returns to page 1.
- A form that saves an idea's tags must start from the tags the idea already has and send them all back (`draftTagIds`); sending `tagIds: []` by default erases them. A form that leaves `tagIds` out leaves the tags alone.
- Anything that shows, picks, or searches Scripture uses `src/features/scripture`. Bible text and the psalm titles are loaded by the migrate command from `data/bible/kjv.json` and `data/bible/kjv-psalm-titles.json`; never edit either file by hand (see `data/bible/README.md`). A psalm's title is never part of a verse.
- The Bible reader's place is its address. Read and write it only through `src/features/scripture/reader-location.ts`, and move within the reader with `window.history.pushState`, not the router.
- In the Bible reader no selection means no verses, never the whole chapter. Use `src/features/scripture/selection.ts`, and add actions on a selection as children of `SelectionToolbar`. The Scripture Panel (`ScriptureBrowser`) keeps its own rule, where an empty choice is the whole chapter; do not change either to match the other.
- Favorites and highlights are `src/features/scripture/saved`. Every query there filters by owner in its WHERE clause, and every one carries a translation (`translation.id`); keep both. A favorite is its verses and its translation, never its label: do not add a second way to save one that goes round `createFavorite`. A verse has one highlight color; a highlight is never stored on a favorite.
- In the reader, an account's marks are read and changed only through `src/features/scripture/use-chapter-marks.ts`, which shows a change at once and takes it back if the server refuses it. `PassageText` draws a highlight behind the words and a selection across the row; keep them apart, a verse can be both.
- Saved Scripture is a section of the library (`/library/scripture`), reached from `LibrarySections`, and is not in the main navigation. Its search, filters, order, and page are URL parameters read and written only through `src/features/scripture/saved/saved-query.ts`, and its controls change the address only through `useSavedScripture().apply`.
- Scripture reaches an existing idea, from anywhere but its own editor, only through `attachReferences` (`src/features/ideas/ideas.ts`) behind the `attachScripture` action, and only through the `AttachScripture` dialog. It adds and never replaces, and locks the idea's row; do not write `idea_scripture_references` another way. A reference is five numbers and no translation: never store verse text or a translation on one.
- A favorite put on an idea is copied as references. Nothing links the two afterwards; do not add a link.
- The reader's address also carries `through` (the end of a passage pointed out) and `idea` (the idea it was opened from), both through `reader-location.ts` like the rest. `idea` is only ever looked up among the signed-in account's own ideas.
- Every string the interface shows comes from `src/i18n/dictionaries/<en|es>/<feature>.ts`, read with `getT` on the server (`src/i18n/server.ts`) and `useT` in Client Components (`src/i18n/client.tsx`). English defines what exists; add a string to both languages. No new English literal in a component, no second copy of a component per language, and no i18n library. A server component shared with tests takes a `locale` prop instead of calling `getT`.
- The interface language and the Bible translation are two preferences on `users`. Saving a different language sets the translation back to null, so it follows the new language until one is chosen again (`saveLocale`); nothing else writes one from the other, and choosing a translation never writes the language. A new account, and a visitor with no language cookie, start in the browser's language (`deviceLocale`, `src/i18n/device.ts`). What is in force comes only from `getPreferences()` (`src/features/preferences/current.ts`), which applies the administrator's Spanish switch; anything that serves Bible text, lists or writes marks, or chooses a language asks it on the server. Never read `users.locale`, `users.bible_translation`, or `app_settings` around it, and never let the switch rewrite a stored preference.
- Bible text is `scripture_verses` / `scripture_psalm_titles`, by translation (`src/features/scripture/translations.ts`). `bible_verses` and `bible_psalm_titles` are superseded: do not read, load, or drop them outside a migration written for that. `data/bible/rvg.json` is written only by `scripts/bible/build-rvg.mjs` from the publisher's file; never edit it, and never alter the wording. The translation is shown as "RVG", never with a year.
- A reference, a favorite's verses, and the reader's place name no translation: both texts number alike. A favorite or a highlight belongs to the translation it was made in and is never shown in, or copied to, the other; the reader says what was marked in the other (`elsewhere`).
- The reader's translation is `t` and its second pane is `beside`, both through `reader-location.ts`. Change the address with `window.history.pushState`/`replaceState` passing `null` as the state, never `window.history.state`: handed its own state back, Next ignores the call. A pane's translation is shown from the reader's own state at once (`chosen`) and must not wait for the address. Comparing is offered only where the window fits two columns, and the docked navigation steps aside for it; do not bring back a one-pane-at-a-time switch.
- The comparison's scroll lock is `src/features/scripture/scroll-lock.ts`, bound only in `BibleReader`. It is optional, off by default, a browser preference (not in the address), never turns a chapter, and is turned off when either pane's chapter changes. The panes still know nothing of each other.
- An idea's status, intended format, and sermon type are the lists in `src/features/ideas/model.ts`, and their words (labels, meanings, a sermon type's definition and example) are in the `ideas` dictionary, read as lists through `classificationOptions` (`src/features/ideas/classification.ts`). Do not write a value or a label anywhere else, add a definitions table, or let an account add a value.
- A status changes only because a person chose it. Nothing sets one from a date, a note, a tag, a passage, or a sermon being preached, and there is no "preached" status, flag, count, or date on an idea: preaching history will hold that.
- Archiving is `archived_at` and nothing else, through `archiveIdea` and `restoreIdea`. It is never a status, never a delete, and never changes another column, `updated_at` included.
- A save of an existing idea is parsed with `ideaUpdate`, where a classification has no default: one left out is left alone. `ideaInput`, which has the defaults, is for a new idea and for a form that sends the whole draft. A form that saves an idea must carry `intendedFormat` in its draft, as the idea page does.
- Since migration `0008` the `ideas` table holds only the current classification values: `status = 'captured'` and a null `sermon_type`, from before Phase 2D.1, were rewritten to `idea` and `unspecified` and are refused by the table. `asRead` in `src/features/ideas/ideas.ts`, which every idea returned from that file passes through, still reads those two as the new values, as a guard for a database the migration has not reached; never read an idea's row around it, never write either old value, and do not teach it to map anything else. Never hand-edit `0008`: its two `UPDATE`s were added to the generated file before it was applied anywhere.
- An idea's status, format, and type are chosen in `ClassificationSection` (`src/features/ideas/components/classification-section.tsx`) and nowhere else. It only changes the draft. A sermon shows all three; a point or an undecided idea shows its status only, and nothing shows, filters by, or infers a format or a sermon type on one.
- Archived ideas are left out by the query, never by the screen. A list of ideas goes through `searchIdeas` (where `LibraryQuery.archive` is `active` unless the address says otherwise) or `recentIdeas`; a new list of ideas must exclude archived ones the same way. `getIdea` returns an archived idea on purpose, so its address and the Bible reader's way back still work; do not "fix" that.
- Main navigation is `src/components/layout/app-links.ts`. Add the outline page there when it exists. Administration stays in the account menu.
- Dropdowns use `src/components/ui/select.tsx`, not a native `<select>`.
